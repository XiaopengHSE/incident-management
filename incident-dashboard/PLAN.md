# 异常事件登记台 — 执行计划

## 原始需求提示
> 生成一个本地"异常事件登记台"：支持新增事件、严重度、负责人、处理状态和备注；支持列表筛选、编辑和关闭事件；提供清晰的空状态、错误提示与 README。不要连接真实业务系统，不使用真实客户数据，不自动发送消息。增加超时提醒、状态历史和导出功能，并让 WorkBuddy 先补测试再改代码。

## 技术方案
- **架构**: 纯前端单页应用，零后端依赖
- **持久化**: `localStorage`（`incident-dashboard-data` 键）
- **样式**: 原生 CSS，桌面窗口自适应（min-width: 900px 推荐）
- **测试**: 独立的 `tests.html` 页面，使用原生断言
- **文件结构**:
  ```
  incident-dashboard/
  ├── index.html      # 主应用
  ├── tests.html      # 测试页面
  ├── README.md       # 使用说明
  ├── PLAN.md         # 本计划文档
  ├── CHANGELOG.md    # 变更记录
  └── FIXLOG.md       # 错误修复记录
  ```

## 功能模块拆解
| 模块 | 功能点 | 测试覆盖 |
|------|--------|----------|
| 事件 CRUD | 新增、编辑、关闭（软删除） | 新增/编辑/关闭断言 |
| 字段体系 | 标题、严重度(紧急/高/中/低)、负责人、状态(待处理/处理中/已解决/已关闭)、备注 | 字段校验断言 |
| 列表筛选 | 按状态/严重度/负责人/关键词筛选 | 筛选结果断言 |
| 空状态 | 无数据时显示引导 | DOM 断言 |
| 错误提示 | 表单校验失败时提示 | 错误消息断言 |
| 持久化 | localStorage 读写 | 刷新后数据存在断言 |
| 超时提醒 | 事件超过设定时间未解决时高亮提醒 | 时间计算断言 |
| 状态历史 | 每次状态变更记录时间戳与操作人 | 历史记录断言 |
| 导出功能 | 导出 JSON / CSV | 导出内容断言 |

## 执行顺序（TDD）
1. 编写 `tests.html` 测试骨架与用例
2. 运行测试（预期：大量失败）
3. 实现 `index.html` 核心功能，使测试通过
4. 实现高级功能（超时提醒、状态历史、导出）
5. 回归测试，修复问题
6. 编写 README
